# 接受判据用配对 bootstrap + 保留/回滚，配轮次与 token 预算

- **Status**: Accepted
- **Date**: 2026-10-15

## Context

单次评测噪声大，直接「谁分高用谁」会把噪声当成进化，导致回归。

## Decision

一轮 = 提案器提出一处编辑 → 跑配对评测 → **接受当且仅当**配对通过率严格提升**且** bootstrap 95% 置信下界 > 0（或至少多过基线 ≥1 例）**且** token 成本不超上限；否则回滚。默认预算 10 轮，每轮 token 有上限。

实现口径（判据落为整数净增）：逐例记 `delta ∈ {-1, 0, +1}`，净增 `net_passes = Σdelta`；「严格提升」即 `net_passes ≥ 1`，与「至少多过基线 ≥1 例」等价。括号里的 fallback 仅在样本量不足以支撑 bootstrap（`count < 2`，重采样区间退化）时启用：此时以 `net_passes ≥ 1` 直接接受；`count ≥ 2` 时以 bootstrap 95% 下界 > 0 为硬门，`net_passes ≥ 1` 但下界 ≤ 0 视为不显著、回滚（避免小样本下把单例翻盘当进化）。

## Considered Options

- **固定胜率阈值**：忽略样本量，小样本下过拟合噪声。
- **全量重跑所有用例每轮**：成本高，且不改变判据本身的统计问题。
